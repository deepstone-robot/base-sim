# 失败模式史

这个项目"训出来一看不对、回头量、再改"的完整记录。**每一行都是一轮真跑的 GPU/CPU 训练**
加上事后 headless 测量。目的不是怀旧，而是：**下一个人想改这些数字之前，先看到代价。**

格式：现象（实测数字）→ 根因 → 修法 → 现在由谁钉住。

## 1. 学会站着不动

- **现象**：500 轮 CPU 训练，第 250 轮还在尝试迈步（有脚离地 32%），第 499 轮变成
  **完美静止**（离地 0.2%，指 0.15 m/s 时一动不动、满回合 4 s 不摔）。
- **根因**（三条叠加）：
  1. `track_lin_vel` 的 `std=0.25` 是给 **4 倍大的指令尺度**配的 ⇒ 站着白拿 71~90% 的跟踪分；
  2. `air_time` 窗口下限 0.125 是当时实际摆动时长（20~30 ms）的 4~6 倍 ⇒ 迈步零梯度；
  3. `action_rate` 权重把 raw 量级估成 ~1.2（真实 5~25）⇒ 权重 -0.30 时占全部罚项 85%，
     而且恰好在"尝试迈步"的窗口加压 ⇒ 有脚离地从 32% 掉到 **0.9%**。
- **修法**：`std` 0.25 → 0.10（后来按真步态再调到 **0.20**）；课程第 1 档下限抬到 0.10；
  `action_rate` 从按"正质量份额"重算。
- **钉住它的测试**：`test_standing_still_cannot_farm_the_top_command`、
  `test_action_rate_weight_curriculum_follows_stages`、
  `test_regularizer_weights_are_sized_by_measured_magnitude`。

## 2. 躺平薅分

- **现象**（250 轮短测）：躯干只有 **0.041 m**、倾角 **50°**、有脚离地 **92%**、所有回合
  `time_out` 永不终止 —— 它把 `air_time` 从 0.08/步薅到 **0.76~1.43/步**（腿举在空中永远满足
  摆动窗口），`track_lin` 还白拿 0.66（零指令时"不动"就是完美跟踪），
  唯一罚它的 `upright` 只有 0.06（而不是 2.0）⇒ 净 **+1.8/步**。
- **根因**：删了高度终止 + 窗口下限 0.03 两处改动叠加，**所有技能类奖励在倒下时仍然可拿**。
- **修法**：`_posture_gate`（软门，乘在三个技能奖励上）+ `fallen_too_long` 终止
  （倒地 1 秒宽限后终止）。修后用同一策略复测：合计 **+1.81 → +0.05**，
  终止原因全变成 `fallen_too_long`。
- **钉住**：`test_posture_gate_matches_measured_postures`、
  `test_gait_rewards_are_gated_by_posture`、`test_fallen_too_long_has_grace_period`。

## 3. 原地蹦

- **现象**（250 轮短测）：离地 **45%**、摆动 121 ms、竖向 `|vz|=0.11`，但**机体系 vx 只有 0.07**
  —— 几乎不位移，`air_time` 却拿到 **2.04/步**（= 跟踪分的 25 倍）。
- **根因**：`air_time` 与**方向无关**。原地蹦也满足"脚离地进了窗口"。
- **修法**：`air_time` 乘**方向进度门**（原地/横着挪 = 0），权重大幅下调 3.0 → 1.5；
  姿态项同时重做（见第 4 条）。净效果（零训练成本重打分）：蹦跳 +2.76 → **+0.18**。
- **钉住**：`test_air_time_requires_commanded_direction_progress`。

## 4. 用 XML 默认姿势当姿态基准

- **现象**：`joint_dev` 用 XML 默认姿势当基准，实测**鸭子站稳时踝关节就比默认转了 17.6°**、
  hip_roll 4.5° ⇒ 等于按"它站不到的姿势"扣分。
- **修法**：改成以**实测站姿**为基准的 `stance_dev`（零动作静置 6 步测出来的偏移），
  并按关节分档 std（hip_roll 0.05 / hip_pitch·knee 0.40 / ankle 0.25 / hip_yaw 0.30）。
- **钉住**：`test_stance_penalty_is_calibrated_on_measured_stance`
  （自然站姿 cost <0.01；叉腿 >1.0；叠正常迈步增量 <0.3）。

## 5. 溜冰 / 前倾蹭地

- **现象**：`air_time` 权重还回 3.0 后第一次出现真正的摆动相（离地 46%、摆动 121 ms），
  但策略变成"不论指令都以 ~0.26 m/s 前进"，`track_lin` 从 1.14 掉到 0.19，零指令时也走并摔倒。
  更早的版本里，步态奖励**相对速度跟踪等于不存在**：旧写法（落脚一次性给分）
  一个周期只有 0.5 分 ≈ **0.014 分/步**。
- **根因**：`air_time` 的"每步付"写法改对了之后权重还偏低（1.5 < `track_lin` 2.0），
  外加它**没有方向门**（见第 3 条）。
- **修法**：`air_time` 再乘跟踪核（超速 1/3.4、乱冲 1/13、零指令 0）、`bad_orientation` 70° → 45°；
  后来又发现那个"跟踪核"因子把速度误差平方级罚了两次（见第 8 条），最终删掉它、
  改用**方向进度门** + 权重 3.0。

## 6. 下巴撑地 / 头撑地（模型层面）

- **现象**：50° 倾角躺着稳稳拿分。根因之一是**几何**：`robot_allcollisions.xml` 有 11 个碰撞面
  （含 `jaw_soft×3` + `hip×2`），鸭子趴/躺/头撑地时**有支撑面**。
  上游文档点名过同一件事（*head-tripod at ~55°*）。
- **修法**：行走任务换 **`robot_walk.xml`**（碰撞面 11 → 5，去掉下巴/髋/躯干碰撞面），
  并在新模型上复核站姿基准（两模型最大差 1.1°，旧表通用）。
- **钉住**：`test_walk_task_uses_the_walk_model_not_allcollisions`。

## 7. 摇头（**判定为机制，不改**）

- **现象**：躯干偏航摆动 ±12.4°、wz RMS 1.86 rad/s（峰值 ≈240°/s）、
  头关节 `head_yaw` 偏离 37.2°（峰值 57°）、嘴尖在躯干系里左右 RMS 33.9 mm / 峰峰 94 mm。
- **测量**（这是关键）：摆动主频 **1.625 Hz ≈ 落脚步频 1.750 Hz**（相位锁在步态上）；
  与左右脚载荷互相关在 **滞后 −3~−5 步（60~100 ms）** 给出 **|r| = 0.59~0.67，8/8 环境一致**
  ⇒ 扭动**先于**抬脚 ⇒ 是倒重心的**机制**。
- **奖励账**：摇头最多让它少拿 0.49/步（`track_ang_vel` 1.0 权重里的一半），
  而它靠这套步态赚 +2.51（`air_time`）+1.90（`track_lin`）。
- **结论**：**不改奖励去压它**。压掉它 = 压掉步态原语本身。
  要让偏航轴听话，正路是**给偏航轴下命令**（turn-in-place 桶）。
- **零成本 A/B 补充**：把头 4 个通道置零（冻结）会让步态明显变差（倾角 1.5°→4.6°、
  侧向占比 21%→59.5%、直线度 0.95→0.66）⇒ **现有策略是靠甩头稳住的**。
  详见 [行走任务](tasks/walk.md) 与 [评估与探针](evaluation.md)。

## 8. 用"真步态"标定奖励（这一轮救回了整条路线）

- **做法**：发现 `../microduck/policies/alpha_walking.onnx` 是上游训练好、真机在用的走路策略，
  接口与我们的环境完全兼容（61 维 obs / `action_scale=1.0` / 同一站姿与关节顺序）。
- **三个收获**：
  1. **它能走**（离地 46%、摆动 170 ms、倾角 2.8°、零摔倒）⇒ 证明我们的环境**能承载**一个真走路策略
     （不是环境写坏了）；
  2. **A/B 对照**：同一策略在**他们自己的环境**里也只能跑到指令的 36~50% ⇒
     那是**他们策略的精度**，不是我们环境的问题（这一条排除了大量无效怀疑）；
  3. **标定出两处校准错误**：`air_time` 上的"跟踪核"把速度误差平方级罚了两次
     （真步态输给站着不动：cmd 0.15 −0.31 / cmd 0.30 −0.55）；`std=0.10` 比真步态的实际精度还严。
- **修法**：去掉跟踪核因子 + `std 0.10 → 0.20` ⇒ **走 > 站 > 溜** 在每个指令下都成立。
- **钉住**：`test_track_std_is_calibrated_against_a_proven_walker`。

## 9. 零成本重打分：差点白跑一轮的地方

- **现象**：改完奖励后，把旧 checkpoint 放进新奖励打分，**排序还是平局**
  （vx=0.15：走路 +2.88 / 站着 +2.82）。
- **测量**：拆项发现 `body_ang_vel` **一项**就占走路罚项的 **-0.426**。
- **修法**：权重 -0.03 → -0.01 ⇒ 排序翻转（+3.17 vs +2.98，vx=0.30 也翻）。
- **教训**：**以后每次改奖励都先做这一步再谈大规模训练。**

## 10. 探针写错三次（脚底离地高度）

| 版本 | 脚踝 ±30° 扫描时的漂移 | 为什么错 |
|---|---|---|
| 脚踝 body 的高度 | **+10.9 mm** | 刚体上的一个点，脚一翻就跟着转 |
| 脚底 site 的高度 | **+14.1 mm** | 同上，而且更糟 |
| 上游那套射线传感器 | 平地上**等于** site 高度 | 射线是竖直的、ring 只在水平面内偏置 ⇒ `min` 退化成 site 自己的高度 |
| **脚底网格采样点取 min** | **≤1.93 mm** ✅ | 对一片点取 min 才是"脚底区域最低点" |

**教训**：探针在换成"更聪明的实现"之前，必须先在**真值已知的极端姿态**下量过漂移。
（注释里还留了点数折中记录：4 mm 网格 53 点 → 1.93 mm；5 mm 网格 34 点 → 4.68 mm。）

## 11. 上游的 `rel_forward_envs` 越过整条课程

- **现象/风险**：上游 `rel_forward_envs` 会把"直行环境"的 vx 硬抬到 **≥0.3 m/s**（Go1 尺度常数）。
  我们的课程第 1 档上限只有 0.20 ⇒ **一打开就越过整条课程上限**，
  而且**不会报错**，会在 GPU 上白跑几千轮才看出来。
- **修法**：`rel_forward_envs = 0.0`，并写测试钉住"起步指令必须落在第 1 档内"。
- **钉住**：`test_startup_command_is_within_first_curriculum_stage`。

## 12. 静默 no-op 家族（配置能跑、训练不报错、什么都没发生）

| 坑 | 后果 | 实测证据 |
|---|---|---|
| `dr.geom_friction` 的 `geom_names=()`（上游模板里的占位写法） | 脚底摩擦一点没随机化 | 改动 **0/76** 个 geom |
| `dr.encoder_bias` 不配 `joint_pos_rel(biased=True)` | 偏置采样了，但策略看不到 | `\|actor观测 − 真实关节角\| = 0.000e+00` |
| `dr.joint_armature` 在我们这版 BAM 下 | 随机值被 BAM 每步覆盖 | 倍数恒为 1.000，跑一步后仍 1.000 |
| 直接写 `body_mass`/`body_inertia` | mjlab 1.3.0 不按环境展开（塌成一个共享值） | 必须走 `pseudo_inertia` |
| 写 `site_quat` 做 IMU 安装误差 | 那些观测项根本不读 `site_quat` | 必须在观测层做 |
| 写 `env.cfg.rewards[...]` 改权重 | manager 初始化时 deepcopy 了 | 必须用 `env.reward_manager.get_term_cfg(...).weight` |
| `dr` 的 `mode="reset"` 事件 | **构造完成时还没生效**，第一条回合是名义参数 | 构造后读字段是 0，显式 reset 一次才 ≤0.003 |

- **钉住**：`test_encoder_bias_dr_only_reaches_the_actor_when_biased_is_set`，
  以及 `scripts/probe_sim2real_dr.py` 的逐项判决表（[sim2real](sim2real.md)）。

## 13. 工具/框架层面的坑

| 坑 | 症状 | 修法 |
|---|---|---|
| `rel_forward_envs` 之外的 `--gpu-ids` 写法 | `Error parsing --gpu-ids: no type matching {None}\|[INT,...]\|{all}` | 省略（默认 GPU 0）/ `--gpu-ids 0 1` / `--gpu-ids all`；**不能给单个裸整数** |
| `episode_length_s` 在构造后修改 | 回合长度不变，症状是"正好在第 200 步全体终止" | 必须在构造前设（`build_env(..., episode_length_s=...)`） |
| viser 摇杆 GUI 的滑块 | `ValueError: add_slider: initial_value (0.05) is outside of [min, max] = [0.1, 10.0]` | 每个指令轴的**上限必须 ≥0.1**；play 模式把 `lin_vel_y` 放到 ±0.10 |
| 原生窗口看多只鸭子 | `A` 键的 "Show all envs" 只影响调试图元，**不画别的环境** | 原生窗口一次只能看一个（`,` / `.` 切换）；要看多只用 viser（`--num-envs 4`，"Hide others" 默认不勾） |
| macOS 起窗口 | `launch_passive requires ... run under mjpython`；窗口"一闪而过" | 必须 `uv run mjpython ...`；且 `launch_passive` 不阻塞，脚本要自己等窗口关闭 |
| 上游 venv 的 warp 缓存 | `os.mkdir` 失败（沙箱拒了 `~/.cache/warp`） | `WARP_CACHE_PATH=$TMPDIR/warp-cache` |

## 复盘：这些坑的共同形状

1. **配置能跑通 + 数字没人看** = 静默错误。这是最大的一类（第 1、2、3、5、11、12 条）。
2. **用别人的常数**（std、`rel_forward_envs`、rail 的摩擦范围、权重）而不按自己的尺子重算
   （第 1、5、11 条）。
3. **探针/判据本身没验证**（第 10 条、以及 `probe_sim2real_dr.py` 里"读错对象导致假结论"的记录）。
4. **改完不回头量**（第 8、9 条的存在就是为了防这个）。

所以本仓库的规矩是：**每个结论都要有一个能复跑的命令，每个坑尽量有一个测试。**
